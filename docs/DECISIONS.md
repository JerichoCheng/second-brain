# 技术决策记录

记录做过的关键决定和原因。推翻某条决定时不要删除，追加一条新记录说明为什么改。

---

### 001 · 只给自己用，不以面试或作品集为目标
2026-10-03

功能取舍以「我每天会不会用」为准，不为展示技术而增加复杂度。

### 002 · 从 RuHua 项目中拆分出来
2026-10-03

原计划把第二大脑和机器人任务规划放在同一个多 Agent 系统里，两者唯一的耦合是共享向量知识库，而这恰好是复杂度最高的部分。拆开后两个项目独立开发；以后如需联动，由第二大脑对外提供接口。

### 003 · 基于 DeepSeek Harness 调用 API，不本地部署模型
2026-10-03

省去本地推理的硬件和维护成本。代价是检索到的笔记和邮件内容会发送给 DeepSeek。

### 004 · 只沿用 Ultimate Brain 的结构，不迁移 Notion 中的内容
2026-10-03

知识库从空开始。保留模板的数据库、字段、视图和工作流（GTD、My Day、My Week），用 schema 文件重新定义。

### 005 · 数据存储为 Markdown + YAML frontmatter
2026-10-03

可以用任何编辑器打开、用 git 管理、agent 直接读取，不被任何软件锁定。数据库视图需要的查询能力由内存索引提供。

### 006 · 不使用 SQLite，用内存索引
2026-10-03

个人知识库规模下（万级文件以内）内存索引足够快，且没有 Electron 原生模块的编译问题。如果将来性能不够再引入。

### 007 · schema 驱动的界面
2026-10-03

所有数据库共用一套视图引擎。新增模块只需写 schema 文件，这让「保留所有模块」在工作量上可行。

### 008 · 桌面框架选 Electron 而不是 Tauri
2026-10-03

Harness 是 Node.js，插件用 TypeScript；Electron 主进程本身就是 Node，整个应用只有一种语言。Tauri 需要额外打包 Node 运行时作为子进程，对个人项目是不必要的复杂度。代价是安装包更大。

### 009 · AI 只能往 Inbox 写提案
2026-10-03

防止模型出错时悄悄改坏正式笔记。由 Harness 的 pre-execute 钩子强制执行，不依赖提示词。

### 010 · 邮件采用固定流水线，而非 agent 自由读取
2026-10-03

抓取 → 本地规则过滤 → 模型分析 → 写入，流程可控、成本可预测。所有邮箱只读访问。

### 011 · 邮件完整正文发送给 DeepSeek
2026-10-03

分析准确度优先。发件人规则命中的推广、通知类邮件不发送。

### 012 · Agent 放在最后一个功能阶段
2026-10-03

前面的功能不依赖 agent 也完全可用；Harness 仍在开发者预览期，越晚接入接口越稳定。

### 013 · 代码仓库与 vault 分离
2026-10-03

本仓库只放代码。vault 包含个人数据（联系人、邮件摘要等），单独存放并用私有仓库备份。
